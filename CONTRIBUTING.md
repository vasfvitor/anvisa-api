# Contributing

This repository has one rule that matters more than the rest: **nothing about the API's
behavior goes in without a recorded response proving it.** ANVISA's spec is wrong in
places, and the value of this project is that every correction here was observed, not
guessed.

## Layout

- `spec/consultas-externas.openapi.json`: ANVISA's document, byte-for-byte. Never edited.
- `spec/consultas-externas.overlay.yaml`: every correction, as an
  [OpenAPI Overlay](https://spec.openapis.org/overlay/v1.0.0.html) action with a comment
  pointing at the evidence.
- `spec/consultas-externas.resolved.json`: output of `make spec`. Committed.
- `fixtures/consultas-externas/`: recorded responses plus `manifest.json` (method, path,
  status, the rate-limit header seen, the request that produced it).
- `packages/python/`: the client. `src/anvisa/models.py` is generated by `make models`;
  everything else is hand-written and should stay small.

## Recording a new response

1. Get credentials from https://api.anvisa.gov.br/ (login Gov.br). Keep them in
   `~/.config/anvisa/credentials.env` with mode 600. Never commit them; never paste a token
   into an issue.
2. Mind the rate limit: 25-request burst, 1 request per second, per client id. A probe
   session should need a handful of requests, not dozens. Reuse the token (it lasts 29 min).
3. Send a descriptive `User-Agent` (Cloudflare blocks curl's default with a 403 HTML page).
4. Save the raw body and headers. Redact nothing but tokens; the shape of the data,
   including nulls and odd values, is the point.
5. Add the body to `fixtures/consultas-externas/` and an entry to `manifest.json` with the
   exact request you sent.
6. If the response disagrees with the spec, add an overlay action with a comment naming the
   fixture, run `make spec models`, and commit the regenerated files with the change.
7. Write a test that parses the fixture into the generated model. That test is the gate
   that the overlay is sufficient.

## Adding a client method

Wrap one endpoint per method; return the generated model; let the existing runtime do auth,
throttling, and error mapping. If the endpoint has a required filter key or ignores
pagination, encode that in the method (raise locally before any request) and in the overlay
(`x-required-filters`, `x-paginated`). Say in the docstring what was verified live and what
comes only from the spec.

## Running things

```bash
cd packages/python && uv sync
uv run pytest             # fixture-only; safe to run on a loop
uv run pytest -m live     # 3 real requests; needs credentials
uv run ruff check . && uv run ruff format .
make spec models          # from the repo root; commit the diff if any
```

## Pull requests

Small and specific. A PR that adds behavior should carry its fixture. A PR that changes the
overlay should carry the regenerated `resolved.json` and `models.py`. CI fails on drift.
